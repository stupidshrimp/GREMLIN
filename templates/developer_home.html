Developer

Four tools, kept apart.

Database inspection reads and only reads: every panel behind it opens GREMLIN.db mode=ro, so it can neither change the file nor take the writer lock other users depend on. User activity reads too, from the access database rather than this one. The other two are consequential — Limble sync writes to the database and spends this server's API credentials, and access control decides who may sign in — so they each get their own page rather than a tab next to something you opened to read.

Database inspection

Read the runtime, the file, the schema and the rows — without touching any of them.

Runtime configuration and registered routes, database file health, ingestion pipeline throughput, the live schema table by table, drift between the code and the file, a paginated row browser and a read-only SQL console.

Limble sync

Run tonight's import now, and watch it work.

The same job the nightly scheduled task runs: pulls tasks and assets from the Limble API, upserts them into the raw import tables and refreshes the mapped layer. Writes to the database. Idempotent, so running it again is safe.

Access control

Accounts, roles and PINs for everyone who signs in to GREMLIN.

Add and remove users, change roles between viewer, editor and administrator, and reset PINs. Stored separately from the analysis database, in {{ access_db_path }}.

User activity

Who is signing in, how often, and what they change once inside.

Sign-ins per account over a window you choose, how recently each account was last used, which have never been used at all, refused and locked-out attempts, and the changes recorded in the audit trail. Read from {{ access_db_path }}.
