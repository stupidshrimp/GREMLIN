Life Data Analysis

Disposition

Disposition each work order once, in fields that serve both the pattern views and Weibull life analysis. The ISO 14224 failure mode, mechanism and cause say how something failed; the sub-asset, component and (when it was one) the part within it say where and what, which is what every Weibull life is measured on. A typical work order is about five picks, each a search of its code list: everything else is derived.

    Configuration

    Disposition code lists

    A component or part is just a name and a description; its code is made from the name when it is added. A code is what dispositions and saved analyses store, so it can't be renamed once added; everything else about it can change. A code nothing uses can be deleted; one in use can only be retired, which takes it off the code fields. Changes reach the open work order at once, and a code you add is set on it, ready to save.

    Disposition helper

    Auto-disposition the backlog

    The helper reads every not-reviewed work order in the list (its search and column filters apply) and dispositions the ones it is at least as sure of as you set here. Each is saved marked Auto, with a review flag, and stays unconfirmed until an engineer opens it and saves it. Perform an Analysis warns when a fit reads any. The whole run can be undone.

    Disposition helper

    How accurate is it?

    The helper reads a work order two ways: it finds the work orders the team has already dispositioned that read most like it, and lets them vote for their codes; and it reads what the work order says outright (“clogged”, “won't light”, “replaced”, “S09”) against the code lists and a thesaurus of maintenance wording. Where the two agree it is sure; where they disagree, or there is little of either, it says so. With meaning matching on, a small model run on this server also finds work orders that say the same thing in other words (“no flame on startup” for “won't light”); it helps find what failed, and the category is still read from the wording.

    To measure itself, it dispositions work orders the team has already decided as if they were new, each one without its own decision, and compares. A confidence of 90% means that nine in ten of its suggestions that sure matched the engineer's disposition.

    Dispositioning explained

    How dispositioning in Excel works

    Excel is the offline version of the list on this page. Download the work orders for the asset you selected, fill in the disposition columns, then upload the same workbook to save them all at once. Nothing reaches the database until you upload it.

    Download Excel → Fill in the disposition columns → Upload Excel
    1. Select the asset and what to show first. The workbook holds the work orders that Show is set to: all of them, only those not reviewed yet, or the migrated ones still to confirm. The search box and the page you are on do not narrow it.
    2. Click Download Excel. The first sheet is one row per work order. The second, Lookup Lists, holds every code with its name and feeds the dropdowns, so leave it in the file.
    3. Fill in the disposition columns, highlighted from the header down: disposition_category, record_class, sub_asset, component_code, part_code, failure_mechanism_code, failure_mode_code, action_code, evidence and failure_cause_code are dropdowns. part_code is optional: the part within the component that failed or was replaced (a filter, an O-ring), blank when the whole component did. renewed_items takes component codes separated by commas; linked_wo the task ID a duplicate continues; qty and disposition_note are typed. Leave failure_cause_code blank to take the mechanism's default cause. A code typed rather than picked can be in any capitals, or its name (Contamination for CONT, PM reset for PM_RESET).
    4. Leave the rest alone. The grey columns are the work order as Limble recorded it and are never written back. mapped_record_id and task_id are how each row finds its work order: don't edit them, and don't copy a row.
    5. Click Upload Excel and choose the file. Only rows whose disposition columns differ from what is saved are saved, through the same checks as Save here, and recorded against your account.
    Worth knowing

    The headings and columns are locked; the cells aren't. Sort, filter, resize, and add or delete rows as you like, but the headings can't be retyped and columns can't be added, deleted or moved, so the upload always finds them. Review > Unprotect Sheet lifts the lock if you must; the upload still reads headings in other capitals or under the names this page uses, a column moved, and a title typed above the table, and tells you about any column it didn't read.

    One refused row saves none. The upload lists every refused row at once, by the row number Excel shows, its task and why; fix them and upload the file again.

    Your team's newer work is kept. Each row remembers the disposition it was downloaded with. If somebody changes a work order here after your download and you leave its row alone, the upload keeps their newer one and says so. If you both changed it, the upload stops and names the row: delete it to keep theirs, or download a fresh workbook and redo it there.

    Uploading the same file twice is harmless: the second time every row already matches.
